# 01. 기획 · 일정 · 역할

출처: `ML_DL 3조 프로젝트.xlsx` — 개발일정표(WBS) 시트

## 서비스 흐름

```
방 사진 업로드 → YOLO 가구 탐지 → 사용자 확인·수정 → 주소·층수 입력
→ 총 부피(CBM) 계산 → 트럭 톤수·대수 산정 → 비용 계산 → 결과 + 3D 적재 시뮬레이션
```

## 설계 진행 순서

1. **근거 데이터 조사**: 이사비용 통계와 요금 정책 사례를 조사했다 → [04 §4 기본요금 근거](04-estimate-policy.md#4-기본요금-산출-근거)
2. **기능 정의**: 화면별 기능명세서를 썼다 → [02](02-functional-spec.md)
3. **견적 산출 정책**: 요금 구조와 요금표를 정했다 → [04](04-estimate-policy.md)
4. **가구 클래스와 기준 사이즈**: 실제 제품(LG, 이케아 등) 치수를 기준값으로 정했다 → [05](05-furniture-data.md)
5. **모델 학습**: 클래스를 53개에서 38개로 정리하고 성능을 분석했다 → [06](06-model.md)
6. **DB 설계**: policy / vision / estimates 테이블을 나눴다 → [07](07-db-schema.md)
7. **구현**: API와 프론트를 만들었다 → [08](08-api.md), [03](03-project-structure.md)

정책 데이터는 엑셀에서 표로 정리하고 INSERT 문을 함께 만들어 두었다가, 지금은 `backend/policy/data/*.csv` + `load_all_policy` 커맨드로 넣는다.
